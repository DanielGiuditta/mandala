MANDALA COMPLETE TEST 1.2.0
ONE PACKAGE. ONE OFFICE SESSION. SEND BOTH REPORTS TOGETHER.

WHAT TO EXPECT
Target: 5-10 minutes of hands-on employee testing after setup, spread across a
roughly 25-35 minute run including restarts/waiting. Setup faults may take longer.
The timer tests click the installed Agent automatically and generate test mouse
activity. Keep this employee PC unlocked and reserved for the test. Do not use it
for other work until finished. The six-minute idle check needs NO keyboard/mouse
input. No screenshots or messages are needed after each step.

BEFORE STARTING
[ ] IT/Windows administrator is available for gateway checks and any installation.
[ ] One dedicated internet-connected gateway and ONE LAN-only employee PC.
[ ] Gateway already installed/configured with MandalaGatewaySetup-1.1.0.exe.
[ ] Employee signs in themselves; no passwords sent to Daniel or typed in checker.
[ ] Two allowed projects agreed for FIVE real test time entries (roughly 0.2 hours
    total, depending on waiting). They will be checked in production afterward.
[ ] Existing employee pairing ZIP available if connection setup is incomplete.
    It must belong to this employee Windows profile; the kit cannot replace keys.
[ ] An internet-connected browser is available for the same employee's short
    browser ownership check. Do not test on a second employee's login.

1. EXTRACT THE WHOLE ZIP ON BOTH PCs
Keep the extracted folder in place through the restart. Do not run from inside
the ZIP. Do not add the test launcher or office setup to Windows Startup.

2. GATEWAY PC FIRST
Double-click "Start gateway Test.cmd". Approve the administrator prompt.
IT confirms the network isolation checklist and that no employee timers are active.
The checker runs all gateway checks, then asks to restart. Save other work first.
Sign back into the SAME Windows administrator account. The one-time test launcher
should reopen; approve its administrator prompt. If it does not, open the same
launcher yourself. Do NOT open gateway setup or start its task manually.
Confirm automatic gateway startup when asked. Collect its desktop report ZIP.
Only continue to the employee if the gateway report says local checks passed.

3. EMPLOYEE PC
Double-click "Start employee Test.cmd" NORMALLY in the employee Windows account.
Enter the employee email. If needed, approve the included installer/startup repair.
Sign in in the real Agent. The checker never reads its password field.
Choose the two agreed projects by number and approve the five real test entries.
Save other work and accept the requested restart.
Sign back into the SAME employee account. The test should reopen automatically;
otherwise open the same employee test launcher. Do NOT open Agent/setup manually.
Confirm whether Agent opened by itself. Sign in in Agent again only if requested.

4. FOLLOW ONLY THE SHORT PROMPTS
- Browser check: on the connected browser, same employee opens project B and tries
  Start Work. Viewing B must leave A running, and browser takeover must be refused.
  Confirm only if BOTH checks pass.
- When asked, disconnect ONLY the employee PC from LAN and confirm. Do not stop
  the gateway. The checker performs the offline stop/reopen/pending tests itself.
- Reconnect when called back and confirm. The remaining project switching and idle
  tests run automatically for about 13 minutes. Leave the PC unlocked and untouched.
The runner reads the Agent's visible state and full save references. It will NOT
invent passes, retry uncertain time writes, shorten the real five-minute idle rule,
read passwords/tokens, change firewall settings, or clear pending work.

5. SEND ONE RESULT SET
Send BOTH desktop ZIPs together:
  Mandala-Quick-Test-<GATEWAY-PC>-gateway.zip
  Mandala-Quick-Test-<EMPLOYEE-PC>-employee.zip
The reports contain all checks, actions in IST/UTC and saved-session references.
No need for screenshots after each step. Keep any MandalaAgentDiagnostics file the
Agent generated during offline testing; provide it only if requested.
Daniel verifies the FIVE real database entries from these reports. Local passes
alone are NOT permission to roll out to the office.

IF SOMETHING FAILS
Read FIXES.txt. All independent checks already collected are in the report.
Before time tests begin, correct a known prerequisite and reopen the SAME launcher.
Once any time test has started, do NOT rerun, reinstall or delete its saved state.
Send the report set even if a check is blocked. Unattempted tests remain BLOCKED.
If disconnected when it stops, reconnect LAN. Preserve any active/pending Agent work.
During automated work hold Escape to stop; the runner leaves existing work intact.
Closing the test window also leaves the last saved report/state; reopen only to
export it. It will not silently repeat a partially completed time test.
